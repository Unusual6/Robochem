1. 项目总览

Robochem-Flex 是 Noël Research Group (NRG) 开发的模块化自驱动实验室框架(Self-Driving Laboratory Framework)， 用于化学反应自动优化。它将机器学习、硬件自动化 与 Streamlit 交互式 GUI 整合为单一生态系统， 支持从配置、运行到结果分析的全流程闭环。

前端 GUI

Streamlit 多页面应用,配置参数与实时监控

硬件层 OmniPlatypus

统一驱动泵、阀、传感器与光谱仪

机器学习 RoBrains

贝叶斯优化、多任务学习、HITL

光谱分析 LAMAS

光谱去卷积与定量分析

平台后端 Backend

桥接 GUI、ML 与硬件的中央协调器

Examples 示例

CS0-CS6 复现 publication 中各场景

核心理念: 平台采用 分层解耦 设计 — 各层通过清晰的抽象基类与参数容器通信, 上层无需了解硬件协议细节,下层不关心优化策略。新增设备或算法只需继承基类、在配置文件中注册即可接入。

2. 系统架构原理

Robochem-Flex 采用经典四层架构,数据流自顶向下,反馈自底向上:

用户 (User)
↓ 配置 / 启动
Streamlit GUI
robochem_flex.py + pages/
ML 后台
RBrains
↓ 参数下发 ↑结果回传
PlatformBackend
backend/platform_backend.py
↓ recipe / ↑ run_result
BaseExperiment
procedures/experiments/
AnalyticsTemplate
procedures/analytics/
↓ 设备指令 ↑测量数据
Platform + Devices
OmniPlatypus
↓ 串口/TCP/Modbus
物理设备
注射泵 / 采样器 / 光谱仪 / 传感器

关键设计模式

  • 模板方法 (Template Method): BaseExperiment 与 AnalyticsTemplate 定义流程骨架,子类覆写 *_procedure 钩子实现具体化学/光化学/热化学反应。
  • 策略模式 (Strategy): ML_classes 字典注册多种优化算法,前端下拉切换。
  • 参数容器 (Parameter Container): NumericalParameter/ExperimentalParameter/AnalyticalParameter 携带值、单位、范围与 foreign_key,跨层翻译不丢失语义。
  • 观察者 (Observer): 设备通过 ParameterCachingPolicy 与后台接收线程,异步推送测量值至缓存。
  • 多线程协调: platform_thread 跑实验,ml_thread 跑优化,frontend_queue 推送日志到 Streamlit。

4. 代码实现解析

4.1 前端入口 (Streamlit GUI)

入口 robochem_flex.py 通过 streamlit run 启动, 在 st.session_state["platform_backend"] 中创建 PlatformBackend 单例, 保证多页面之间共享状态。 

if "platform_backend" not in st.session_state:
    st.session_state["platform_backend"] = PlatformBackend(st.session_state)
backend = st.session_state["platform_backend"]

各页面文件按编号顺序自动激活,典型页面:

  • pages/02_用户设置.py — 用户名、实验名、平台选择
  • pages/03_物理参数.py — 物理参数(温度、停留时间等)定义
  • pages/04_试剂.py — 化学物质、储备液、样品瓶布局
  • pages/05_分析.py — 选择分析技术(下拉框),渲染 analytical_parameter
  • pages/06_机器学习.py — 选择 ML 算法、目标、参数空间
  • pages/07_运行平台.py — 校验、启动/关机按钮、实时结果展示

4.2 平台后端 (PlatformBackend)

backend/platform_backend.py 中的 PlatformBackend 是整个系统的中央协调器, 继承 BaseLoggedClass,持有:

  • session_container: SessionContainer 实例,管理可序列化的会话状态
  • platform_config: 从 config/platform_config.json 加载的设备/常量字典
  • ML_classes: ML 算法注册字典,前端下拉项与其一一对应
  • platform_constructors: 实验流程类(Photochemical/Thermochemical/DryRun)
  • _rolling / _emergency_stop: threading.Event 控制运行状态
  • platform_experiment / platform_thread / ml_thread: 运行时实例与线程

ML 算法注册字典示例

ML_classes = {
    "BO_optimisation":         SingleBayesianOpti,
    "BO_optimisation_HITL":    SingleBayesianOptiHITL,
    "EfficientBatchedBO_HITL": EfficientBatchedBO_HITL,
    "MultiTaskScope":          MultiTaskScope,
    "MultiTaskScope_HITL":     MultiTaskScope_HITL,
    "ScopeAcceleratorTask":    ScopeAcceleratorTask,
    "EnantioExtravaganza":     EnantioExtravaganza,
    # "MyCustomML":            MyCustomML,   # ← 二次开发时取消注释
}

4.3 硬件层 (OmniPlatypus)

4.3.1 设备基类 BaseDevice

devices/base/device.py 定义所有设备的统一接口,核心抽象:

  • ParameterAccess 枚举: R / W / RW
  • ParameterCachingPolicy 枚举: NEVER / TRY / ALWAYS
  • DeviceParameter: 描述参数的元信息(访问级别、缓存策略、值类型、单位)
  • __getitem__ / __setitem__: 通过 self['param_name'] 读写参数

这意味着上层代码可以不感知协议细节,例如:

# 通用方式驱动任何设备
device['start_wavelength'] = 500.0
device['start_scan'] = True
data = device['data']

4.3.2 设备驱动实例 — U3900H UV-Vis

devices/nrg/u3900h_spectrometer.py 演示了自定义 TCP 设备如何接入平台:

  • STX/ETX 二进制帧协议: _encode_frame / _decode_frame / BCC 校验
  • 后台接收线程 _recv_thread 持续读取 socket,推送至内部缓存
  • threading.Lock 保证并发安全
  • 注册 DeviceParameter: start_wavelength, end_wavelength, scan_speed, data, start_scan, baseline_calibrate, selftest, status, scan_progress

4.3.3 Platform 类与设备构建

devices/platform.py 中的 Platform 类按 platform_config.json 中 devices 段落自动实例化所有设备:class 字段映射类名,serial.known_device 通过 serial_id.py 自动绑定 USB 端口,setup 字段传入构造参数。

4.3.4 实验流程基类 BaseExperiment

procedures/experiments/base_experiment.py 定义实验骨架:

  • _analytical_methods: dict[str, ExperimentAnalysisCoupler],声明本实验支持的所有分析技术
  • _required_parameters / _optional_parameters: 参数约束声明
  • _required_devices: 必需设备名集合
  • start() / submit_run() / get_results() / stop(): 运行生命周期
  • 含 *_procedure 钩子方法,子类覆写
  • 内置 _run_requests_queue: Queue 实现异步调度

4.3.5 ChemicalReaction 实战示例

procedures/experiments/chemistry.py 的 ChemicalReaction 注册了 5 种分析方法: 

_analytical_methods = {
    "Human":      ExperimentAnalysisCoupler(analysis_class=None,           ...),
    "NMR_dummy":  ExperimentAnalysisCoupler(analysis_class=DummyNMRAnalysis,...),
    "NMR":        ExperimentAnalysisCoupler(analysis_class=NMRAnalysis,     ...),
    "UPLC":       ExperimentAnalysisCoupler(analysis_class=HPLCAnalysis,   ...),
    "Raman":      ExperimentAnalysisCoupler(analysis_class=AnalyticsRaman, ...),
    "UV":         ExperimentAnalysisCoupler(analysis_class=AnalyticsU3900H,...),
}

每个耦合器声明 analytical_device(对应 platform_config.json 中设备名)与 platform_constants_key(对应 constants.analysis 段)。新增 UV 通道只需新增一行注册。

4.4 机器学习 (RoBrains)

ML 后端继承 通信模块 + ML 模块 双重基类,例如 SingleBayesianOpti 同时继承 SingleBayesianOptiBackend(算法) 与 ML_Platform_HITL(通信),保证算法与平台解耦。 

class SingleBayesianOpti(SingleBayesianOptiBackend, ML_Platform_HITL):
    """Single-task Bayesian Optimization with HITL support."""
    pass

关键流程

  1. ML_prime(ml_parameters, targets, path): 初始化参数空间、目标、会话路径
  2. comm_prime(kwargs): 与硬件层建立通信
  3. first_run(): Sobol 采样生成初始点
  4. 主循环 run():
    • 从 results_df 训练代理模型 (SingleTaskGP + Standardize)
    • 优化采集函数 (qExpectedImprovement / qLogExpectedImprovement)
    • 调用 _to_machine(tensor) 把张量翻译为 ExperimentalParameter 列表 (recipe)
    • 通过通信模块下发 recipe,等待硬件回传结果
    • 调用 _to_ml(result) 把结果翻译为 (x, y, y_var) 张量
    • 写入 utilities_df 与 results_df

张量 ↔ 参数翻译 (_to_machine / _to_ml)

ToandFromMachine 类(backend/ml_backends.py)是 ML 层与硬件层的语义桥梁: 每个参数通过 foreign_key 关联 ML 张量位置(check_dict), translation_continuous / translation_discrete / translation_task / translation_fidelity 完成连续/离散/任务/保真特征的编码与反编码。

_sampling_priorities 字典定义了不同试剂类型(Limiting Reagent / Catalyst / Solvent 等)的采样优先级, 用于 slug 生成时的体积分配排序。

4.5 光谱分析 (LAMAS)

LAMAS 提供光谱去卷积与定量分析能力。在 Robochem-Flex 中, procedures/analytics/analytics_template.py 的 AnalyticsTemplate 是统一入口, 各具体分析类继承它并通过 _processing_methods 暴露可选数学方法。

AnalyticalParameter(procedures/analytics/analytics_parameters.py) 携带 tag 字段(如 "all"、"simple_integration"), 前端 pages/05_分析.py 通过 backend.get_analytic_parameters() 按 tag 过滤参数,实现"选择数学方法 → 显示对应参数"的动态渲染。

5.1 典型优化运行流程

用户:
  1. 在 GUI 配置:平台(Perry)、实验类型(PhotochemicalReaction)
     → 参数空间(温度、停留时间、催化剂当量、光强)
     → 分析技术(Raman 或 UV) → ML 算法(BO_optimisation)
  2. 保存会话 → 点击 "启动"

PlatformBackend.start():
  3. build platform (按 platform_config 实例化设备)
  4. 启动 platform_thread 跑 BaseExperiment.start()
  5. 启动 ml_thread 跑 ML_instance.first_run() + run()

ML 主循环 (SingleBayesianOptiBackend):
  6. 训练 SingleTaskGP(X, Y)
  7. 优化 qExpectedImprovement → 下一个 tensor
  8. _to_machine(tensor) → recipe (List[ExperimentalParameter])
  9. 通信模块下发 recipe → BaseExperiment.submit_run()
 10. ChemicalReaction 执行:采样 → 注入 → 反应 → 分析 → 收集
 11. AnalyticsU3900H.analyse() 返回 RunResult(yield, integral, absorbance_at_wlen)
 12. _to_ml(result) → (x, y, y_var) 写入 results_df
 13. 回到步骤 6,直至达到 Number of total points 或终止条件

6.2 自定义设备驱动 (以 RamaBerry Raman 光谱仪为例)

参考实现: devices/nrg/rama_berry.py。 Raman 光谱仪通过树莓派上运行的 RamaBerryPy 服务端应用对外提供 JSON-over-Socket 协议, 因此驱动继承 SocketDevice 而非直接继承 BaseDevice — 后者已封装 socket 生命周期,新驱动只需关注业务命令。

步骤 1:继承 SocketDevice,注册参数表

# devices/nrg/rama_berry.py
from omniplatypus.devices.base.device import (
    DeviceParameter, ParameterAccess, ParameterCachingPolicy, ParameterEnumValue
)
from omniplatypus.devices.base.device_socket import SocketDevice
from bidict import bidict

# 可选: 定义枚举型参数值(用于离散选项)
class DataPollerStyle(ParameterEnumValue):
    _raw_values = bidict({
        "SERVER_SINGLE":   "SERVER_SINGLE",
        "SERVER_KINETIC":  "SERVER_KINETIC",
    })

class RamaBerry(SocketDevice):
    def __init__(self):
        SocketDevice.__init__(self)
        self.generic_name = "Raman Spectrometer"

        # —— 11 个参数,覆盖全部协议命令 ——
        # 1. 积分时间 (ms),范围 100~50000,只写
        p = DeviceParameter(name="integration_time", access_level=ParameterAccess.W,
                            value_type=float, internal_id=201)
        p.units = "ms"; p.caching_policy = ParameterCachingPolicy.ALWAYS
        p.min_value = 100.0; p.max_value = 50000.0
        self.add_parameter(p)

        # 2. 平均次数 (RW, int)
        # 3. delay / 4. n_scans / 5. save_as (DataPollerStyle 枚举)
        # 6. dark_correction (bool) / 7. data (pd.DataFrame, 只读)
        # 8. start_acq / 9. stop_acq (bool 触发型, RW)
        # 10. save_moniker (str) / 11. save_path (str)
        # ... 每个 DeviceParameter 都通过 self.add_parameter(...) 注册

    # —— 协议层 ——
    def _send_command(self, command: str, data=None):
        """JSON over TCP: 发 {command[, data]}, 收 4 字节长度前缀 + JSON 响应"""
        payload = {"command": command}
        if data: payload["data"] = data
        self._socket.sendall(json.dumps(payload).encode())
        data_len = int.from_bytes(self._socket.recv(4), "big")
        # 循环 recv 拼接,直到达到 data_len
        return json.loads(full_response)

def open(self, host: str, port: int):
    """打开连接: 先 SSH 启动树莓派上的 server,再建立 socket"""
    self._start_server(host, "Raman")    # 见下方

    self._initialized = True

def _start_server(self, host, username):
    """通过 paramiko SSH 到树莓派启动 RamaBerry_listener.py
    前提: ~/.ssh/id_rsa 已配置免密登录"""
    ssh = paramiko.SSHClient()
    ssh.set_missing_host_key_policy(paramiko.AutoAddPolicy())
    private_key = paramiko.RSAKey.from_private_key_file(
        os.path.expanduser("~/.ssh/id_rsa"))
    ssh.connect(host, 22, username=username, pkey=private_key)
    ssh.exec_command("""

步骤 3:重写 _write / _read 把参数映射到协议命令

def _write(self, parameter: DeviceParameter, value):
    """写参数: 区分"触发型命令"与"普通参数设置" """
    if parameter.name == "start_acq" and value is True:
        # 触发采集 → 发 start_acq 命令,完成后把缓存值复位为 False
        self._send_command("start_acq")
        parameter.value = False
        parameter.last_known_value = False
    elif parameter.name == "stop_acq" and value is True:
        self._send_command("stop_acq")
        parameter.value = False
    elif parameter.name == "save_as":
        # 枚举型: 转成小写字符串再下发
        self._send_command("set_params", {parameter.name: value.value.lower()})
    else:
        # 普通参数: 统一走 set_params 命令
        self._send_command("set_params", {parameter.name: value})

def _read(self, parameter: DeviceParameter):
    """读参数: data 走 get_data,其它走 get_params"""
    if parameter.name == "data":
        return pd.DataFrame(self._send_command("get_data")["data"])
    return self._send_command("get_params", {"name": parameter.name})[parameter.name]

关键设计要点:
  • 分层继承: RamaBerry → SocketDevice → BaseDevice,socket 协议样板由 SocketDevice 提供,业务驱动只关心命令语义。
  • 触发型参数: start_acq / stop_acq 是 bool 但语义是"按下按钮",_write 中识别为命令并在执行后自动复位缓存。
  • 枚举型参数: 通过 ParameterEnumValue + bidict 定义离散可选值,前端下拉框自动渲染。
  • 缓存策略: 大部分参数 ALWAYS(只在 init 时读),data 必须 NEVER(每次实时拉取最新光谱)。
  • 外部服务依赖: open() 内嵌 SSH 启动树莓派上的 RamaBerry_listener.py 服务端,真正的硬件控制在远端,本机只走 TCP。
