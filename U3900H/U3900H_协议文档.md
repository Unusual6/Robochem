# U3900H USB 通信协议文档

> 依据 `U3900H_gateway_and_driver.py` 逆向实现整理。  
> 设备：日立 U-3900H 分光光度计（USB Bulk）。

---

## 1. USB 传输层

| 项 | 值 |
|---|---|
| VID | `0x04A4` |
| PID | `0x0073` |
| Interface | `0` |
| OUT Endpoint | `0x04` |
| IN Endpoint | `0x85` |
| 传输方式 | USB Bulk |
| 驱动要求（Windows） | WinUSB（可用 Zadig 安装） |

读写均通过 Bulk 端点完成；上层协议帧直接作为 Bulk payload 收发。

## 2. 帧格式

所有命令与响应均使用同一帧结构：

```
+------+----------+------------------+------+-----+
| STX  | Length   | Payload (ASCII)  | ETX  | BCC |
| 1B   | 4B BE    | N bytes          | 1B   | 1B  |
+------+----------+------------------+------+-----+
```

| 字段 | 长度 | 说明 |
|---|---|---|
| STX | 1 | 起始符，固定 `0x02` |
| Length | 4 | Payload 字节长度，**大端** |
| Payload | N | ASCII 文本命令/响应 |
| ETX | 1 | 结束符，固定 `0x03` |
| BCC | 1 | 校验字节 |

### 2.1 BCC 计算

```
BCC = XOR(Length || Payload || ETX) XOR 0x02
```

即：对 Length(4) + Payload + ETX 逐字节异或，再与 `STX(0x02)` 异或。

### 2.2 编解码示例（Python）

```python
STX, ETX = 0x02, 0x03

def calc_bcc(length4: bytes, payload: bytes) -> int:
    x = 0
    for v in length4 + payload + bytes([ETX]):
        x ^= v
    return x ^ 0x02

def encode(payload_ascii: str) -> bytes:
    payload = payload_ascii.encode("ascii")
    length4 = len(payload).to_bytes(4, "big")
    bcc = calc_bcc(length4, payload)
    return bytes([STX]) + length4 + payload + bytes([ETX, bcc])
```

## 3. 命令约定

- Payload 为 **ASCII 字符串**，字段之间用**定宽空格**分隔（空格数量敏感，不可随意改）。
- 命令码一般为 8 位十六进制字符串，如 `00010002`、`00010800`。
- 响应通常以状态/应答码开头，格式类似：

```
00000600 00010800 <field3> <field4> ... [波长] [吸光度]
```

---

## 4. 状态字段说明

通过状态查询命令 `00010800` 解析：

| 字段 | 位置（按空格分割） | 含义 |
|---|---|---|
| reply_code | tokens[0] | 应答码（常见 `00000600`） |
| echo_cmd | tokens[1] | 回显命令（如 `00010800`） |
| field3 | tokens[2] | 过程状态 |
| field4 | tokens[3] | 设备状态码 |

### 4.1 field3（过程状态）

| 值 | 含义 |
|---|---|
| `00` | 空闲 / 完成 |
| `01` | 自检中 |
| `02` | 基线校准中 |

### 4.2 field4（设备状态码）

| 值 | 含义 |
|---|---|
| `00000000` | 就绪 / 完成 |
| `00000200` | Ready（可执行业务） |
| `00000A00` | Busy（忙碌） |

### 4.3 常见错误码

| 值 | 含义 |
|---|---|
| `00001500` | 命令格式错误或参数无效 |

### 4.4 就绪判定（业务常用）

设备可进行下一步操作时，通常要求：

- `field3 == "00"`
- `field4 in ["00000000", "00000200"]`

建议连续轮询稳定 N 次（代码默认 2~3 次）后再发下一命令。

## 5. 基本设备功能命令

### 5.1 命令一览

| 命令码 / Payload | 功能 | 说明 |
|---|---|---|
| `00010002` | 读取 ID / 版本 | 自检第 1 步 |
| `00010810` | 初始化 / 读取大状态 | 自检第 2 步，耗时较长 |
| `00010300` | 设置 / 初始化模式 | 自检第 3 步 |
| `00010100 ...` | 方法参数设置 | 起止波长、扫描速度等 |
| `00010800` | 状态轮询 | 查询 field3/field4、可选波长吸光度 |
| `00010323  1` | 启动基线校准 | **两个空格** + `1` |
| `00010500` | 开始扫描测量 | 进入测量流程 |
| `00010801   <wv>` | 设置波长并测点 | 波长保留 4 位小数，前有 **3 个空格** |
| `00010302  0  0` | 结束扫描测量 | 定宽空格 |

---

### 5.2 读取 ID / 版本

**命令**

```
00010002
```

**用途**：读取设备标识/版本信息。  
**超时建议**：5s，可重试。

---

### 5.3 初始化 / 读取大状态

**命令**

```
00010810
```

**用途**：设备初始化并读取完整状态。  
**注意**：耗时可能较长，建议超时 ≥ 10s。

---

### 5.4 设置 / 初始化模式

**命令**

```
00010300
```

**用途**：完成模式初始化。  
**后续**：轮询 `00010800`，直到 `field3=00` 且 `field4=00000000`。

---

### 5.5 方法参数设置（波长扫描）

**命令模板**（空格数量需严格匹配捕获格式）：

```
00010100   <mode>  <scan_speed>  <p3>  <p4>  <p5>   <scan_speed_value>   <start_wv>   <end_wv>  <p9>   <p10>  <p13>   <p11>  <p12>   <p14>  <p15>  <p16>  <p17>  <p18>     <p19>  <p20>  <p21>   <p22>    <p23>
```

**默认示例**

```
00010100   17  3  0  0  1   300.0   534.00   200.00  0   1.0  1   500  0   325.00  1  1  1  1     0.00  0  0   340.00    120.0
```

**关键参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| mode | `17` | 模式 |
| scan_speed | `3` | 扫描速度编码（对应 300 nm/min） |
| scan_speed_value | `300.0` | 扫描速度实际值（nm/min），1 位小数 |
| start_wv | `534.00` | 起始波长（nm），2 位小数 |
| end_wv | `200.00` | 结束波长（nm），2 位小数 |

**注意**

1. 命令必须带齐全部参数，否则设备可能回退默认波长范围（如 400–500 nm）。
2. 若响应含 `00001500`，通常表示格式/参数错误。
3. 发送后需轮询状态至就绪。

---

### 5.6 状态轮询

**命令**

```
00010800
```

**响应示例结构**

```
00000600 00010800 <field3> <field4> ... [xxx.xxxx] [±x.xxxxe±xx]
```

**解析规则（实现侧）**

- 波长：形如 `xxx.xxxx`（4 位小数），范围约 `150~1000 nm`
- 吸光度：科学计数法，如 `1.2345e-02`
- 若同帧有多个候选，波长可按期望值就近匹配，吸光度取最后一个

---

### 5.7 基线校准

**命令**（空格严格：`00010323` 后 **两个空格**，再 `1`）

```
00010323  1
```

**流程**

1. 轮询确认设备就绪（`field3=00`，`field4∈{00000000,00000200}`）
2. 发送 `00010323  1`
3. 继续轮询：校准中 `field3=02`，完成后 `field3=00` 且 `field4` 就绪
4. 建议超时 180s

---

### 5.8 开始扫描测量

**命令**

```
00010500
```

进入点测/扫描流程后，再循环发送波长设置命令。

---

### 5.9 设置波长（单点测量）

**命令**（`00010801` 后 **三个空格**，波长 `.4f`）

```
00010801   600.0000
```

**响应**：包含对应波长与吸光度；解析后得到 `(wavelength_nm, abs)`。

---

### 5.10 结束扫描测量

**命令**

```
00010302  0  0
```

结束后轮询直至 `field3=00` 且 `field4=00000000`（可连续稳定 3 次判定完成）。

## 6. 推荐业务流程

### 6.1 启动自检 + 方法设置

```
00010002
  → 00010810
  → 00010300
  → 轮询至 field3=00, field4=00000000
  → 00010100（方法参数）
  → 轮询至 field3=00, field4∈{00000000,00000200}
```

### 6.2 基线校准

```
确认就绪
  → 00010323  1
  → 轮询至 field3=00, field4就绪（过程中 field3 可能为 02）
```

### 6.3 扫描测量

```
00010500
  → 循环：00010801   <wv>  （按 start→end、step 步进）
  → 00010302  0  0
  → 轮询至 field3=00, field4=00000000
```

波长步进方向由 `step` 正负决定：

- `step > 0`：递增直到超过 `end`
- `step < 0`：递减直到低于 `end`

## 7. 通信注意事项

1. **空格定宽**：多个命令依赖固定空格数量，错误空格会导致参数错位或 `00001500`。
2. **串行互斥**：同一时刻只发一条命令，等完整帧响应后再发下一条（实现中用 USB 锁保护）。
3. **超时与重试**：普通命令 5s；`00010810` / 方法设置建议更长；超时可重试 2~3 次。
4. **粘包/半包**：IN 端可能返回多帧或部分帧，需按 STX/Length/ETX/BCC 做帧同步缓冲解码。
5. **状态防抖**：关键状态切换建议连续稳定轮询后再继续，避免抖动误判。

## 9. 附录：完整帧十六进制示意

以 payload = `00010800` 为例：

1. Payload ASCII：`30 30 30 31 30 38 30 30`（8 字节）
2. Length：`00 00 00 08`
3. STX：`02`，ETX：`03`
4. BCC：`XOR(00 00 00 08 + payload + 03) XOR 02`
5. 最终帧：`02 | 00 00 00 08 | 30 30 30 31 30 38 30 30 | 03 | BCC`
